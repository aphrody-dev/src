# Ecosystem Choices for `ay`

Which crates and CLIs to adopt as tooling moves into the single Rust multicall CLI `ay` (`crates/ay`, see
[`NAMING.md`](./NAMING.md)), with Bun packages covering the web side. Targets: `x86_64-pc-windows-msvc`,
`x86_64-unknown-linux-musl` (static), macOS, `wasm32`.

Snapshot taken 2026-11-12. Columns:

- **Version / date**: latest stable release and its publication date, from
  `https://crates.io/api/v1/crates/<name>` or `gh api repos/<o>/<r>/releases/latest`.
- **DL total / 90d**: crates.io total and recent downloads.
- **Rdeps**: count from `/reverse_dependencies`.
- **Stars**: GitHub stars.
- **Win / musl / wasm**: support for each target. `Y` means yes, `N` means no, `P` means partial (see the
  note).
- **Used**: whether the repo already uses it, in `Cargo.toml`, `crates/*/Cargo.toml`, `~/.local/bin` or
  `~/.cargo/bin`.

Reproduce or refresh any row with `curl -H 'User-Agent: x' https://crates.io/api/v1/crates/<name>`.

## Selection rules (from the engineering guidance consulted)

- Microsoft Pragmatic Rust Guidelines ([all.txt](https://microsoft.github.io/rust-guidelines/agents/all.txt)):
  - `M-APP-ERROR`: applications use one app error type (`anyhow`). Libraries keep canonical error structs
    (`thiserror`).
  - `M-MIMALLOC-APPS`: applications set mimalloc as the global allocator.
  - `M-CARGO-WORKSPACE`: shared dependencies go in `[workspace.dependencies]` with `default-features = false`.
  - `M-OOBE`: a crate builds with only cargo and rustc. This favours `ring` and pure-Rust codecs over cmake or
    nasm C builds.
  - `M-STATIC-VERIFICATION`: clippy, cargo-audit, cargo-hack, udeps and miri run as gates.
- Chromium (`third_party/chromium/src/third_party/rust/README-importing-new-crates.md`, local mirror):
  - Every crates.io import goes through `gnrt` and is vendored.
  - A shipping crate that contains `unsafe` needs a security review against the rule of 2; crates that fail it
    are confined to the `sandbox` group. We apply the same idea: prefer crates with `#![forbid(unsafe_code)]`
    or small audited `unsafe`, and run `cargo deny` / `cargo audit` (both installed in `~/.cargo/bin`).
- Linux kernel Rust ([docs.kernel.org/rust](https://docs.kernel.org/rust/index.html)) does not pull from
  crates.io and builds against pinned in-tree crates. The lesson here is to pin and vendor, not which crates to
  pick.
- [blessed.rs](https://blessed.rs/crates) recommendations:
  - HTTP and async: `reqwest` / `ureq`, `axum` ("recommend for most new projects"), `tokio`.
  - Crypto and TLS: `rustls`.
  - CLI: `clap`, with `bpaf` and `lexopt` as alternatives.
  - Terminal: `ratatui` plus `crossterm`, `indicatif`.
  - Errors: `anyhow` / `thiserror`.
  - Other: `jiff` for time, `tracing` for logging, `directories` / `etcetera` for platform directories.
- Awesome lists checked:
  - [awesome-rust](https://github.com/rust-unofficial/awesome-rust) lists russh, boringtun, rustic, bollard,
    hickory, smithay, ratatui, bottom, keyring, sysinfo, youki, brush, nushell and rclone.
  - [awesome-sysadmin](https://github.com/awesome-foss/awesome-sysadmin) lists restic, rclone and coolify.
  - [awesome-selfhosted](https://github.com/awesome-selfhosted/awesome-selfhosted) lists infisical and vector.
  - [awesome-wayland](https://github.com/natpen/awesome-wayland) lists smithay.
  - [awesome-tuis](https://github.com/rothgar/awesome-tuis) lists ratatui and bottom.
  - Also checked: [awesome-cli-apps](https://github.com/agarrharr/awesome-cli-apps),
    [awesome-wasm](https://github.com/mbasso/awesome-wasm) and
    [awesome-bun](https://github.com/apvarun/awesome-bun).
- Repo constraints:
  - Bun built-ins come before npm on the web side (`CLAUDE.md`).
  - The Go deploy engine (`infra/go.mod`) has zero dependencies and calls provider REST APIs directly.
  - `crates/remote` already chose `ring` over `aws-lc-rs` so it needs no cmake or nasm on Windows or musl.
  - Windows links use `rust-lld` and sccache is disabled for incremental builds
    ([`BUILD_SPEED.md`](./BUILD_SPEED.md)).

## Adopt now in `ay` (ordered by impact)

1. Upgrade `ureq` 2.12 to 3.5.1 in `[workspace.dependencies]`. It is used by `crates/up` and others and is
   the network base for every provider verb. Keep the ring-backed `rustls`; add `platform-verifier`.
2. Ship `ay` through **dist** 0.34.0, with self-update via **axoupdater** 0.10.3 (`ay self update`). This gives
   msvc, musl and macOS archives, installers and receipts.
3. Store secrets with **keyring-core** 1.0.1 and the native store crates (`ay secret get/set`). Use **age**
   0.12.1 for files and headless hosts; use sops for anything committed.
4. Build `ay remote exec` fanout on the existing **russh** 0.65.1 and **russh-sftp** 3.0.1: a JoinSet with a
   concurrency cap, `indicatif` 0.18.6 `MultiProgress`, plus `russh-config` and `pageant` for `~/.ssh/config`
   and the Windows agent.
5. Install and run services with **service-manager** 0.11.0, **windows-service** 0.8.1 and **sd-notify** 0.5.0
   (`ay service install/start/status` on Windows, systemd and launchd).
6. Add **object_store** 0.14.2 (R2, S3, GCS) for artifacts and `ay up` mirrors, and keep **rclone** as the
   external sync CLI.
7. Embed **ubi** 0.13.0 in `ay up` for GitHub-release binaries, instead of hand-rolled asset matching.
   `src.lock.json` stays the truth.
8. Supervise child processes with **process-wrap** 10.0.1 (whole-tree kill via Job Objects / process groups)
   for `ay deploy`, `ay test` and `ay wl` children.
9. Load config with **config** 0.15.27 (`ay.toml` plus `AY_` environment overrides) and write with
   **toml_edit** 0.25.
10. Back up with **rustic_core** 0.13.0 (`ay backup`), restic-compatible.
11. Schedule with **croner** 4.0.3 plus tokio (`ay cron`); use apalis only if durable queues appear.
12. Export telemetry with **opentelemetry-otlp** 0.33.1 and **tracing-opentelemetry** 0.34.0 behind a
    feature flag; run Vector on hosts.
13. Set **mimalloc** 0.1.52 as the global allocator of the `ay` binary (`M-MIMALLOC-APPS`).
14. Use **bollard** 0.21.1 for `ay deploy` local image builds and inspection; use oci-client 0.18.0 for
    registry pushes without a daemon.
15. Use **hickory-resolver** 0.26.3 for `ay net dns` diagnostics (DoH, DNSSEC, record types beyond A/AAAA).
