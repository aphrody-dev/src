# Toolchain upstream levers

Source-level review of the toolchains the monorepo builds with, aimed at a flat
Rust 2024 + Bun + Chromium tree on Windows 11 (x86_64-pc-windows-msvc, 24 logical
CPUs, NTFS `C:`, no Dev Drive) plus the Linux containers (Alpine/musl `builder`
and `runtime`, Arch/glibc `dev`).

Every claim cites `repo@commit path:line` at the commits below. Where a claim rests
on something not read in source (tool behaviour, external docs), it says so.
This document changes no build configuration; `.cargo/config.toml` and the
profiles are being tuned separately and the recommendations below are input for
that work.

## Top 10 levers

Ordered by expected gain per unit of effort for this repo:

1. **D10 + W1**: Defender exclusions plus a Dev Drive for `build-dir`, ccache and ThinLTO caches. Helps cargo, Bun and Chromium at once.
2. **C3/C4**: short `build.build-dir` path. The new per-unit layout adds one `-L` per dependency, and with sccache as wrapper this is the most likely cause of `os error 206`.
3. **C6**: `-Zfeature-unification` with `resolver.feature-unification = "workspace"`, so `-p` builds stop rebuilding shared dependencies.
4. **R13**: `rust-lld` as the windows-msvc linker for dev and test binaries.
5. **R5/C2**: Cranelift for workspace members in dev (LLVM for dependencies), excluding crates whose tests need unwinding.
6. **R8**: an internal `lto = "thin"`, `codegen-units = 16`, `incremental = true` profile next to the fat-LTO dist profile. Post-LTO modules get reused.
7. **R1**: `-Zthreads=4..8` for dev and check builds, validated with `cargo build --timings` (C8) and `-Zself-profile` (R11).
8. **B5/P1**: ThinLTO cache plus `-gcodeview-ghash` in the Bun fork's Windows link. Also check B10 (is JSC being built locally?).
9. **B3**: install ccache for Bun's C/C++ (picked up automatically). Use `--lto=off --rust-lto=off --rust-codegen-units=16 --rust-incremental=on` for release iteration (B6).
10. **C5**: checksum freshness in the Linux containers, where Docker Desktop bind mounts make mtimes unreliable. For Chromium, iterate in `out/Default`, not `out/Release`, and use `--no-history` for fresh checkouts (D2, D8).

Already on, no action: `-Zembed-metadata=no` on nightly (C1), share-generics in dev (R4), rust-lld on x86_64 Linux GNU (R12/G2). No effect, remove or document: `split-debuginfo = "unpacked"` on Windows (R15), `/DEBUG:FASTLINK` in lld (L3), `enable_nacl` (D9).

## Patches worth carrying

rustc, cargo, LLVM, gcc, glibc and depot_tools need no patches: every lever above is a configuration change. The two patches below are in the Bun fork, where the build flags are hard-coded and have no environment hook.

1. **P1: ThinLTO cache and precomputed type hashes in the Bun Windows link** (`third_party/bun/scripts/build/flags.ts`, the release entry at `1167-1200` and the `/Z7` entry at `342-347`).
   - Add `/lldltocache:<cacheDir>/thinlto` and `/lldltocachepolicy:cache_size=10%:cache_size_bytes=40g:cache_size_files=100000`, copied from Chromium's policy (`chromium/src/build/config/compiler/BUILD.gn:788-800`).
   - Add `--thinlto-cache-dir` for the ELF lane.
   - Add `-gcodeview-ghash` next to `/Z7`.
   - Why a patch: `flags.ts` takes no extra linker flags from the environment, and lld only caches when the flag is passed (`lld/COFF/LTO.cpp:212-213`).
   - Gate: local builds only (not `cfg.ci`), the same rule the fork already uses for `-Zthreads`, so release artifacts stay byte-reproducible.
2. **P2 (optional): a `release-fast` build profile** in `third_party/bun/scripts/build/profiles.ts` (next to `release-local`, `139-144`).
   - Settings: `lto: false, rustLto: false, rustCodegenUnits: 16, rustIncremental: true`.
   - Mirror `rustCodegenUnits` and `rustIncremental` to `CARGO_PROFILE_DEV_*` (`scripts/build/rust.ts:663-670`).
   - Also add `[profile.dev.package."*"] debug = "line-tables-only"` to the fork's `Cargo.toml`.
   - Why a patch: the four flags in B6 work today, but there is no way to make them one named profile or apply them to dev.
   - Low priority: carry it only if the long flag line becomes a habit.

Rejected as patches:

- sccache support in the Bun ninja graph (B2): it depends on wrappers forwarding rustc's JSON artifact notifications.
- Blobless clones in gclient (D4): high maintenance, and `--no-history` covers most of the benefit.
- Swapping the host linker for Bun build scripts (B9): small gain, and the fork documents why it chose `link.exe`.
