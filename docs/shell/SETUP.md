# Shells: reproducible installation (2026-11-13)

A single environment source for all shells, configs versioned in the repository, a verifiable lock. Windows (the PC) and Linux (prd, fr1, fr2) use the same files.

## Shared layer (`packages/machine/shells/`)

| File | Role |
|---|---|
| `env.toml` | single source: SRC_ROOT, AY_SHELL_CACHE, XDG (Linux only), LANG, EDITOR/VISUAL/PAGER, CARGO_HOME/RUSTUP_HOME/BUN_INSTALL, Deno/JDK/Android/Ghidra (Windows), npm, telemetry off, PATH (`front` = entries moved back to the front), `persist.windows` (HKCU) |
| `env.sh` `env.ps1` `env.nu` `env.fish` | generated by `shells.ts --gen`, do not edit. Idempotent, no subprocess |
| `manifest.toml` | `[[link]]`: repository config -> location expected by the shell (`source` = one-line stub, `copy` = copy) |
| `shells.lock.toml` | version, upstream URL, sha256 of the asset (gh api), b3sum of the installed binary, hosts |
| `bash/` (agent A, [bash-setup.md](bash-setup.md)) · `pwsh/` (agent B, [pwsh-setup.md](pwsh-setup.md)) · `nu/` · `fish/` | per-shell configs |
| `completions/ay.{yaml,fish,nu}` | generated from `ay --help` (clap and argh): carapace spec (bash, pwsh, nu), fish completions, nushell `extern` |

Commands (repository root):

```
bun packages/machine/src/shells.ts --gen        # regenerates env.* and completions/ay.*
bun packages/machine/src/shells.ts              # generates + deploys the links + nu caches (idempotent)
bun packages/machine/src/shells.ts --check      # drift: generated files, links, lock, HKCU, pinned folders (exit 1)
bun packages/machine/src/shells.ts --only nu,fish,carapace   # restricts the deployed [[link]] entries
bun packages/machine/src/apply-user.ts [--check]             # includes shells.ts
```

Measured pitfalls, handled by the generator:
- PATH in the bash family on Windows: niubash and brush accept `C:/x;…` (`;` separator), Git Bash (`BASH=/usr/bin/*`) requires `:` and `/c/x`. env.sh picks the form at run time.
- niubash 1.5.0: `${PATH//…}` costs 40 to 100 ms per call on a long PATH. env.sh tests membership with `case` and removes an entry with `%%`/`#*`. Measured cost of `. env.sh`: +11 ms (22.0 -> 33.2 ms, hyperfine).
- pwsh: no cmdlet in env.ps1. A cmdlet loads its module, and 12 `Get-Command` cost ~115 ms. PATH processed in one pass (List + case-insensitive HashSet).
- On Windows, do not set XDG_CONFIG_HOME: nushell and git would look for their config in `~/.config`.
- `HKCU\Environment`: POWERSHELL_TELEMETRY_OPTOUT and POWERSHELL_UPDATECHECK must exist before pwsh starts (about_Environment_Variables 7.7). `--check` checks them without writing them; nt-d6 applies them.

## nushell

- Binary: official MSI 0.117.0 in `%LOCALAPPDATA%\Programs\nu\bin\nu.exe`. `~\.cargo\bin\nu.exe` is a copy of it (identical b3sum `00443a42…`), to be deleted.
- Stubs `%APPDATA%\nushell\{env,config}.nu` -> `nu/env.nu` (which sources `../env.nu`) and `nu/config.nu`. Config keys were verified with `config nu --doc` (0.117.0); `str downcase` is deprecated since 0.114.0, use `str lowercase`.
- Startup without external process. zoxide and carapace are pre-generated in `vendor/autoload` (`ay-zoxide.nu`, `ay-carapace.nu`), the upstream autoload mechanism, loaded after config.nu.
- Completions: `ay` goes through native `extern`s (120 signatures, `completions/ay.nu`); git, cargo, bun and just go through the carapace 1.8.2 external completer, with the `ay.yaml` spec in `%APPDATA%\carapace\specs`.
- Aliases never shadow a built-in command: `ls`, `find`, `du` and `ps` stay structured.

## fish

- No native upstream Windows build. The 4.9.3 README points to WSL, Cygwin or MSYS2, all three excluded; issues #4212 and #10155 are closed ("requires a POSIX-compatible environment"), and the `openhoangnc/fish4win` fork has been inactive since 2021. fish is therefore used only on the Linux fleet. prd has it via pacman (4.9.3). For the other hosts: upstream static asset (`shells.lock.toml`) or home-manager.
- Stub `~/.config/fish/config.fish` -> `fish/config.fish`, which sources `../env.fish`. `fish_add_path -gPm` comes from `fish_add_path --help` on prd. The interactive part sits behind `status is-interactive; or return 0`, with the zoxide init cached in `$AY_SHELL_CACHE/fish` and abbreviations rather than aliases.
- Completions: fish's own for git, cargo and just (79, 56 and 68 entries on prd), and `completions/ay.fish` in `~/.config/fish/completions`.

## Nix (Linux)

- Nix is installed on no host as of 2026-11-13. fr2 keeps the `nixbld*` accounts of a removed installation, without `/nix`. The hosts are not modified.
- `infra/fleet/nix/` contains a standalone home-manager flake (`root@prd`, `ubuntu@fr1`, `ubuntu@fr2`) that reads `packages/machine/shells`. The options were verified in `nix-community/home-manager` (modules/programs/{bash,fish,nushell,carapace,zoxide}.nix). Built on 2026-11-13 in the `nixos/nix` container (Nix 2.35.6) on prd, from a git checkout: `nix build .#homeConfigurations."root@prd".activationPackage` succeeds, and the relative path `../../../packages/machine/shells` is accepted, because a flake in a git subfolder has the whole repository as its root. Smoke test with the store packages: nu 0.116.1 and fish 4.9.3 load the repository configs (SRC_ROOT=/root/src, EDITOR=nvim, 119 ay `extern`s). `flake.lock` pins nixpkgs d4f25a3e (2026-11-11) and home-manager 82ce401a (2026-11-10).
- Verdict: for 3 hosts with native distributions (pacman, apt), `shells.ts` under bun is enough, and home-manager is not required. The flake is ready if a host moves to Nix. Gap to report: nixpkgs (nixos-unstable) is still on nushell 0.116.1, while the lock pins 0.117.0.
