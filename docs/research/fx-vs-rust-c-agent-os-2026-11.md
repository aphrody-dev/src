## 1. Diagnostic : Pourquoi `fx` (Zig 0.17.1) ET `brush-core` ont ete ecartes

### 1.1 Purge de `fx` (Zig 0.17.1)

L'ancien coeur Zig `fx` compilait une bibliotheque partagee `fx_capi` depuis un fork d'agent de terminal. Quatre defauts structurels l'excluent d'un vrai OS Unix cross-platform pour agents :

1. **Couplage TUI massif (~70 % de l'arbre Zig)** : `src/ui/render_engine/*`, `src/ui/footer/*`, `src/ui/transcript/*` dupliquent les TUI hotes (`agy`, Claude Code, `opencode@2.2.7` / `opentui@v0.8.4`).
2. **Faux sandbox par heuristique lexicale** : `src/core/permissions/auto_classifier.zig` filtre des chaines shell par regex sans isolation par capacites (WASI/FD), ni Library OS, ni micro-VM hyperviseur sous Windows NT + Linux.
3. **Surface C ABI triviale** : `fx_capi` n'exposait que trois utilitaires de texte (`fx_strip_ansi_json`, `fx_display_width`, `fx_parse_blocks_json`), absorbables dans `aphrody_core_capi`.
4. **Rupture de la chaine ThinLTO LLVM 24** : `build.zig` produisait un binaire separe hors du graphe Cargo + Clang (`crates/core-capi`).

### 1.2 Pourquoi `brush-core` (`reubeno/brush`) est incomplet et refuse comme autorite

Contrairement a une lecture superficielle des README, nos propres campagnes de conformite ([MATRIX.md](file:///C:/src/docs/shell/MATRIX.md), [rust-bash-reimpl.md](file:///C:/src/docs/shell/rust-bash-reimpl.md), [DEDUP.md](file:///C:/src/docs/unixwin/DEDUP.md)) demontrent que **`brush` (`0.4.0` / `brush-core@0.5.0`) est incomplet pour un OS Unix cross-platform d'agents** :

- **Echec sur `shell-matrix`** : `brush` `0.4.0` plafonne a **`30/34`** et `brush` `main` (`e9d45efe`) a **`31/34`** (echecs sur `bash-procsub`, `win-cd-drive`, `win-cd-native`), contre **`34/34` pour `niubash` (`rubash`)**.
- **37 issues Windows ouvertes et bloqueurs critiques** : blocage des pipes `> 4096` octets (`#1359`), `PATHEXT` casse sur `.cmd`/`.bat` (`#1317`, `os error 193`), chemins relatifs apres `cd` non resolus (`#1251`), quoting externe vers binaires Win32 (`#1295`), `declare -f` corrompant les heredocs (`#1580`), `shopt -s globstar` accepte mais `**` non recursif (`#1581`), `wait -n` et `disown` absents, et **aucune translation de chemins POSIX/Windows** (`/c/...`, `/mnt/c/...`, `/cygdrive/c/...`, `pwd -W`).

## 3. Architecture d'Execution Retenue pour `@aphrody/ai-os`

1. **C ABI unique (`aphrody_core.h`)** : [ai_os.rs](file:///C:/src/crates/core-capi/src/ai_os.rs) expose le VFS FHS (`ai_os_uname_json`, `ai_os_vfs_resolve_json`), `/dev/llm` (`ai_os_llm_spec_json`), `/dev/rag` (`ai_os_rag_*`), `/dev/world` (`ai_os_world_*`) et `/dev/sys1` (`ai_os_sys1_decide_json`), charge via `bun:ffi` dans [cabi.ts](file:///C:/src/packages/ai-os/src/core/cabi.ts).
2. **Trois anneaux d'execution Unix cross-platform (Windows 11 NT natif + Linux `fr1`/`prd`)** :
   - **Anneau 0 (In-process / WASM `< 1 ms`)** : `OverlaySandbox` (`runJustBash` VFS Copy-on-Write + `runSandboxedJs` Worker isole dans [sandbox.ts](file:///C:/src/packages/ai-os/src/core/sandbox.ts)) et `wasmsh` (`0.9.0`, shell + coreutils Rust compiles en WASM sans syscall hote).
   - **Anneau 1 (Vrai Userland Unix/GNU Natif Cross-Platform)** : moteur Rust **`rubash` / `niubash` `1.5.0`** (`34/34` `shell-matrix`, `124/124` e2e GNU Bash `5.3.20`, dialectes `/c/`, `/mnt/c/`, `pwd -W`) + **`yash-rs`** (POSIX.1-2024 strict) + **`uutils` (`coreutils` `0.12.0`, `findutils` `0.11.0`, `diffutils-flat`, `sed`)** + **`WinuxCmd`** (`176` commandes, `rust2/`), confines par `cap-std`, `landlock`/`seccompiler` (Linux) et JobObjects/AppContainer (`windows-sys`).
   - **Anneau 2 (Isolation Kernel / Hyperviseur pour binaires non fiables)** : **`microsoft/litebox`** (Library OS Rust Win32 + Linux) et **`hyperlight`** (micro-VM WHP sous Windows / KVM sous Linux en `~1-2 ms`).
