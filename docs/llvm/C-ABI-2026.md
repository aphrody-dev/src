## Pièges ABI

- **Win64 vs SysV** : Win64 = 4 registres (rcx, rdx, r8, r9), shadow space 32 o, struct > 8 o ou taille non puissance de 2 passée par pointeur ; SysV = 6 registres entiers + 8 SSE, struct ≤ 16 o éclatée en registres [NV, connaissance générale]. Conséquence : ne jamais supposer qu'un struct de 12/16 o « passe en registres ».
- **Retour de struct** : sret caché différent entre MSVC/SysV et pour les méthodes C++ (MSVC renvoie toujours par sret pour les non-POD) [NV]. Règle : retourner un code d'erreur, sortie via pointeur.
- **`long double`** : 64 bits sous MSVC, 80 bits x87 sous SysV/MinGW [NV]. Interdit dans l'API.
- **`bool`, enums C** : taille d'enum = `int` côté C, `#[repr(C)]` côté Rust ; préférer `uint32_t` + constantes.
- **C++ MSVC vs clang-cl** : clang-cl vise la compatibilité ABI MSVC (mangling MS, layout, EH) et lie la STL Microsoft (Learn clang-support-msbuild) [V]. Exceptions : `[[no_unique_address]]` ignoré par MSVC, il faut `[[msvc::no_unique_address]]` [NV] ; `__declspec(empty_bases)` change le layout et casse l'ABI si non appliqué partout (Learn « empty_bases », 2026-11-12) [V]. Vécu : port Oils, `Token : loc_t, word_t` → seule la première base vide à l'offset 0, `tag()` lit le mauvais `ObjHeader` ; corrigé par `OILS_EMPTY_BASES` (docs/shell/oils-windows.md) [V].
- **Mangling** : Itanium (`_Z…`) sur Linux/macOS/MinGW, MS (`?…@@`) sur msvc ; jamais d'API C++ à la frontière.

## Règles `depot-capi`

1. Une seule ABI exportée : C (C11 sous-ensemble compatible C23), `extern "C"` + `#[unsafe(no_mangle)]` en Rust, `extern "C"` en C++. Pas de crABI, abi_stable, safer_ffi.
2. En-tête généré par **cbindgen** (pin 0.29.x), vérifié en CI (diff = échec). Consommateurs C/C++ externes : **bindgen** 0.73.x. diplomat évalué seulement si besoin de bindings idiomatiques multi-langages.
3. Types autorisés : `intN_t`/`uintN_t`, `size_t`, `double`, pointeurs opaques (`typedef struct depot_x depot_x;`), `struct` `#[repr(C)]` ≤ 16 o sans padding implicite. Interdits : `long`, `long double`, `bool` dans les structs, `_BitInt`, unions, bitfields, enums typées.
4. Erreurs : chaque fonction renvoie `int32_t` (0 = ok) ; sorties par pointeur ; message via `depot_last_error(buf, len)`. Aucun panic/exception ne traverse : `catch_unwind` en Rust, `noexcept` en C++ ; `panic=abort` acceptable.
5. Mémoire : qui alloue libère (`depot_x_free`). Chaînes = `(const uint8_t*, size_t)` UTF-8, pas de NUL obligatoire.
6. Versionnage : `depot_abi_version()` + préfixe `depot_` ; ajout seulement, jamais de changement de layout (struct avec champ `size` en tête si extensible).
7. Callbacks : `void* user_data` + pointeur de fonction ; pas d'appel ré-entrant depuis un thread non enregistré (.NET, JSC).
8. Liaisons : bun → **Node-API** en prod (`bun:ffi` réservé aux outils internes) ; Node → Node-API ≤ 10 ; .NET → `LibraryImport` + `DirectPInvoke`/`NativeLibrary` (lib statique `.lib` en NativeAOT) ; exports .NET → `UnmanagedCallersOnly`.
9. Windows : tout en ABI msvc (clang-cl/lld-link ou cl/link) ; aucune lib windows-gnu liée dans `depot-capi`. Classes C++ internes à bases vides multiples : `empty_bases` macro obligatoire, `static_assert(sizeof/offsetof)` par cible.
10. Tests ABI : `static_assert` de tailles/offsets générés côté C et `const _: () = assert!(size_of::<T>() == N)` côté Rust, sur linux-gnu et windows-msvc (cargo-xwin sur prd).
