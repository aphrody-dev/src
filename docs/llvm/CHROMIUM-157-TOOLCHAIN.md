# One toolchain with Chromium 157: clang, lld and rustc on LLVM 24 (2026-11-13)

Owner rule: src builds with the toolchain Chromium ships, so C, C++ and Rust share one LLVM and
cross-language LTO works (`docs/llvm/UNIFIED-TOOLCHAIN.md` section 1). Until today the root
`rust-toolchain.toml` pinned `nightly-2026-11-12` (LLVM 23.1.5) while Chromium 157 is LLVM 24.
This file records the switch and its proof.

## The toolchain

From `third_party/toolchain-157.toml` (Chromium prebuilts, `tools/clang/scripts/update.py` and
`tools/rust/update_rust.py` of the fr1 checkout, Chromium 157.0.8103.78):

| Part | Version |
|---|---|
| clang, lld, llvm-* | clang 24.0.0git (llvm-project 86922d51, `llvmorg-24-init-7747-g62397f8b-67`) |
| rustc, cargo, clippy, rustfmt, rust-src | rustc 1.100.0-nightly (1edd55dcf 2026-09-09), cargo 1.100.0-nightly (3c0b53475), LLVM 24.0.0 |

Checked live with `--version` / `rustc -vV` on fr1 (`/srv/chromium/src/third_party/...`) and on the
PC after `bun scripts/toolchain.ts install`.

## How it is installed

`bun scripts/toolchain.ts install` downloads the host's packages from Chromium's public bucket
(`source_url` of the manifest), checks `source_sha256`, unpacks them under
`~/.local/share/aphrody/toolchain/157/{clang,rust}` (`$AY_TOOLCHAIN_DIR` overrides) and runs
`rustup toolchain link chromium-157 <rust>`. `rust-toolchain.toml` names that toolchain, so cargo,
rust-analyzer and clippy pick it everywhere. `status` prints both versions; `env` prints CC/CXX/AR
and the cross-language LTO `RUSTFLAGS` (Linux: clang + `-fuse-ld=lld`; Windows: clang-cl +
lld-link, Chromium's Windows package has no `clang` driver). The CI installs it first:
`ci.yml` (fr1 runner) and `judge.yml` (ubuntu-latest, for `cargo metadata`).

Unpacking is not compiling: the PC holds the toolchain for rust-analyzer and clippy and still
compiles nothing.

## Proof (fr1, 2026-11-13)

- `cargo +chromium-157 test -p aphrody-bun-flat -p aphrody-docs -p aphrody`: 71 + 16 + 6 tests pass
  (main at f8ac686), with `CARGO_PROFILE_DEV_CODEGEN_BACKEND=llvm`.
- `cargo +chromium-157 build --release -p aphrody` with Chromium's clang as linker, `-fuse-ld=lld`,
  `-Clinker-plugin-lto`, `CC/CXX=clang`, `AR=llvm-ar` of Chromium: builds in 10 min 12 s,
  `ay 0.2.0`, 39.2 MB. The C of the dependency tree (ring, aws-lc-sys, bundled SQLite) is compiled
  by the same LLVM 24 and LTO'd with the Rust.
- The workspace's `cargo-features = ["codegen-backend", "panic-immediate-abort"]` is accepted by
  cargo 1.100.

## What changed in the repository

| File | Change |
|---|---|
| `rust-toolchain.toml` | `channel = "chromium-157"`, components rustfmt, clippy, rust-src (no Cranelift) |
| `Cargo.toml` | `[profile.dev]` no longer selects `codegen-backend = "cranelift"`: Chromium's rustc has no Cranelift backend |
| `scripts/toolchain.ts` | installer, status, env (bun) |
| `.github/workflows/ci.yml`, `judge.yml` | toolchain step before cargo |
| `infra/docker/Dockerfile` | `RUSTUP_TOOLCHAIN=${RUST_TOOLCHAIN}` for the Alpine images (exception below) |

## Exceptions, stated and not hidden

- **Alpine musl containers** (`infra/docker`): Chromium ships std for `x86_64-unknown-linux-gnu`
  (and the Windows host) only, no musl std. The images keep `nightly-2026-11-12` (LLVM 23) through
  `RUSTUP_TOOLCHAIN` until a `-Zbuild-std` musl build with the Chromium toolchain is proven.
- **Windows binary**: cross-compiled on fr1 with `cargo xwin` and `-Zbuild-std=std,panic_abort`
  from the toolchain's rust-src (no prebuilt windows-msvc std in the Linux package); that build
  was still running when this file was written. Until it passes, the dist release
  (`release.yml`, generated by dist, also macOS which has no package in the manifest) is not
  switched.
- **The bun fork** (`third_party/bun`) is its own workspace and keeps `nightly-2026-09-15`
  (LLVM 23) until bun is ported to LLVM 24 (`UNIFIED-TOOLCHAIN.md` section 2).
- **Build speed**: the dev profile loses Cranelift; `docs/BUILD_SPEED.md` numbers for Cranelift no
  longer apply to the default profile.
