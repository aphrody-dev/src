# Accessibilité web

Spec `web.a11y` · domaine `a11y` · sources lues le 2026-11-13 · JSON : [`web.json`](./web.json) (schéma `../spec.schema.json`).

Exigences d'accessibilité pour toute interface web ou WebUI de src. Référence normative : WCAG 2.2 (w3.org/TR/WCAG22, Recommandation du 12 décembre 2024), citée par numéro de critère sans recopie. Guide d'application : web.dev/learn/accessibility. Outillage : axe-core et Lighthouse.

Synthèse normative réécrite ; aucun passage recopié. Textes sources sous CC BY 4.0 (code Apache 2.0), © Google LLC et auteurs cités, sauf WCAG 2.2 (W3C Document License, cité par numéro).

Niveaux : MUST, MUST-NOT, SHOULD, SHOULD-NOT, MAY au sens de la RFC 2119.

## Conflits et réserves relevés

- web.dev/learn/accessibility/color-contrast définit le grand texte gras comme « 14 pt / 18,5 px » ; 14 pt valent 18,67 px (14 × 4/3) : on retient la définition en points de WCAG 2.2.
- La même page renvoie vers les documents Understanding de WCAG 2.1 alors que web.dev/learn/accessibility/forms cite WCAG 2.2 : la cible est WCAG 2.2, qui conserve 1.4.3.
- WCAG 2.2 marque 4.1.1 Parsing comme obsolète et retiré : aucun contrôle de parsing n'est exigé.
- Taille de cible : WCAG 2.5.8 (AA) fixe 24 × 24 px CSS ; l'audit SEO Lighthouse tap-targets vise 48 × 48 px. Les deux sont tenus : 24 en MUST, 48 en SHOULD (seo.web).
- 2.3.3 Animation from Interactions est de niveau AAA ; la règle mouvement réduit l'élève en MUST par décision de spec.
