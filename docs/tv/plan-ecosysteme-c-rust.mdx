# Plan écosystème C et Rust fusionné (monorepo `tv`)

Principe : Rust possède l'architecture, la mémoire, la concurrence, le réseau, l'UI et les formats où une crate mature existe. Le C (FFmpeg et bibliothèques de référence) reste derrière une frontière FFI étroite : crates `-sys` générées par bindgen, une crate wrapper sûre par bibliothèque, aucun type C exposé hors du wrapper. Versions de crates : voir remplacant-ffmpeg-rust.mdx ; toute version non listée là est nv.

Graphe (sens « dépend de ») :

- `tv-core` ← tout le reste ; `tv-ffi-util` ← tous les `-sys` wrappers.
- `tv-container`, `tv-codec` ← `tv-ffmpeg`, wrappers C, crates Rust pures.
- `tv-filter` ← `tv-codec`, `tv-render`, `tv-color` ; `tv-hw` ← `tv-core`, `tv-color`.
- `tv-pipeline` ← container, codec, filter, hw, audio, subs.
- `tv-stream`, `tv-net` ← `tv-pipeline` ; `tv-iptv` ← `tv-net`, `tv-meta`.
- binaires ← `tv-pipeline`, `tv-stream`, `tv-net`, `tv-iptv`, `tv-i18n`, `tv-render`.

## Frontière FFI

- `-sys` : bindgen à la compilation si `TV_REGEN_BINDINGS`, sinon bindings pré-générés commités par cible (évite libclang en CI).
- Wrappers : RAII (`Drop` appelle `av_*_free`), `Send` seulement si documenté thread-safe, aucun pointeur brut public, `#![deny(unsafe_op_in_unsafe_fn)]`, chaque bloc `unsafe` commenté `// SAFETY:`.
- Données : zéro copie via `AVBufferRef` emballé ; frames GPU via handles (CUDA, `VkImage`, `ID3D12Resource`).
- Callbacks C (I/O avio) : `extern "C"` + `catch_unwind`, jamais de panique à travers la frontière.

## Build

| Option | Usage | Décision |
|---|---|---|
| vcpkg (triplet x64-windows-static-md) | dav1d, opus, libwebp, libavif, libjxl, x264, x265, libvpx, ffmpeg | défaut Windows |
| pkg-config | Linux, GStreamer local | défaut Linux |
| vendored (`cc`/`cmake`/meson dans `build.rs`) | FFmpeg configuré minimal, SVT-AV1, vvenc | feature `vendored` pour builds reproductibles |
| Toolchain | `x86_64-pc-windows-msvc` | MSVC : compatible vcpkg, D3D12, MF ; GNU non supporté |

- NASM 3.02 requis (dav1d, x264, FFmpeg asm). sccache activé.
- Features Cargo : `ffmpeg`, `dav1d`, `rav1d`, `svt-av1`, `rav1e`, `x264`, `x265` (GPL), `vpx`, `vvc`, `opus`, `jxl`, `avif`, `webp`, `placebo`, `nvidia`, `vulkan-video`, `d3d12`, `mf`, `srt`, `webrtc`, `moq`, `gpl` (agrégat), `nonfree` (refusé par défaut).

## Tests et qualité

- FATE : exécuter `make fate` sur le FFmpeg vendored ; échantillons FATE réutilisés comme corpus de non-régression pour les implémentations Rust (sortie bit-exacte ou CRC frame-par-frame vs libavcodec).
- Fuzzing : cargo-fuzz sur chaque démuxeur Rust, parseur M3U/XMLTV/MPD, RPU Dolby Vision ; corpus partagé ; ASan sur wrappers FFI.
- Miri sur `tv-core`, `tv-ffi-util` (hors appels C).
- cargo-nextest ; tests de propriété (proptest, nv).

## CI

- Windows MSVC (principal), Linux x86_64, macOS (nv runner) ; cache sccache + vcpkg binaire.
- Jobs : fmt, clippy `-D warnings`, nextest, cargo-deny, fuzz 10 min/cible la nuit, FATE hebdo, bench sur runner GPU dédié (RTX 4070 local).
