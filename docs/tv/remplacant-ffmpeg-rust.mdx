## Conclusion

(a) Aucun remplaçant unique en Rust. oxideav, seul « FFmpeg en Rust » trouvé, est embryonnaire (0.0.6, 5 étoiles). Le seul framework complet avec une API Rust est GStreamer + gst-plugins-rs, mais son cœur et beaucoup de codecs restent en C.

(b) Architecture « full Rust » réaliste :

- Rust pur : mp4-atom, matroska-demuxer + webm-iterable, mpeg2ts-reader, m3u8-rs, dash-mpd, symphonia, rav1e, rubato, fast_image_resize, yuvutils-rs ou dcv-color-primitives, wgpu (conversion et rendu sur DX12/Vulkan/WebGPU), retina, str0m, moq-lite, xiu, lofty, srtlib.
- Rust (port) : rav1d pour le décodage AV1, à la place de dav1d.
- Bindings minimaux : SDK NVIDIA (NVENC/NVDEC) via cudarc + nvidia-video-codec-sdk, ou vk-video (Vulkan Video) ; libopus via opus ; OpenH264 en repli logiciel H.264. Chaque binding lie une seule bibliothèque, jamais FFmpeg entier.

(c) Manques sans solution Rust en novembre 2026 :

- décodeurs logiciels HEVC, VP9 et VVC en Rust pur ;
- encodeurs logiciels H.264/HEVC en Rust de niveau x264/x265 ;
- surcouche Rust maintenue pour D3D12 Video ou Media Foundation (seulement windows-rs brut) ;
- SRT maintenu (srt-tokio inactif depuis 05/2024) ;
- muxer MPEG-TS Rust pur autonome (nv) ; sous-titres ASS/WebVTT complets (nv) ;
- équivalent de libavfilter et de la couverture de formats FFmpeg.
