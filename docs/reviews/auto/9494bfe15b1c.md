**Note : 13/20.** Le commit ne contient que du reformatage, donc je note surtout la cohérence du formatage et les défauts qu'il laisse en place. Je n'ai pas relu les fichiers entiers, seulement le diff.

**Défauts vérifiables**

1. **`.claude/workflows/gemini-review.js`, l.5-6 (`whenToUse`).** Le formateur a laissé cette chaîne en apostrophes alors que tout le reste est en guillemets doubles, à cause des `"` internes. Le style n'est donc pas uniforme.
   - Correction : passer en guillemets doubles avec échappement, ou en template string.

2. **`.claude/workflows/gemini-review.js`, `pipeline`/`agent` (diff l.82-93).** Les interpolations de `${file}` et `${d.claim}` sont mises dans un prompt entre guillemets sans échappement. Un nom de fichier ou une claim contenant `"` casse le prompt.
   - Correction : passer par `JSON.stringify(file)` et `JSON.stringify(d.claim)`.

3. **`.claude/workflows/gemini-review.js`, `review.defects.map` (diff l.100).** Si `review.defects` est absent ou non tableau, l'appel lève une exception. Le schéma marque `defects` comme requis, mais rien ne le garantit à l'exécution.
   - Correction : utiliser `(review.defects ?? []).map(...)`.

4. **`.claude/workflows/gemini-review.js`, `return results...` (diff l.117-123).** `r.defects.filter` et `d.verdict?.real` supposent que `defects` existe. Un verdict `undefined`, par exemple après un échec d'agent, n'est classé ni confirmé ni réfuté, donc il disparaît du rapport.
   - Correction : ajouter un tableau `unverified`.

5. **`packages/core/src/generate.ts`, `PILLARS` (l.21-45).** Deux sources sont à `verified: false`. La ligne `"https://llvm.org/docs/ (LLVM 24.0.0git)"` n'est pas une URL valide parce qu'elle contient du texte. Elle sera rendue telle quelle dans `- [NV] url`.
   - Correction : mettre l'URL seule et la version dans un champ séparé.
   - Ces entrées `[NV]` sont aussi publiées dans les skills générés. La règle « aucune version sans source vue » n'est pas respectée.

6. **`packages/core/src/generate.ts`, `testedUsers`, requête `rustTests` (diff l.176-185).** La requête repère les tests Rust avec `name = 'tests' AND kind = 'module'`. C'est une heuristique fragile : un module `tests` qui n'est pas annoté `#[cfg(test)]` est compté quand même.
   - Correction : utiliser un indicateur `is_test` stocké à l'indexation.

7. **`packages/core/src/generate.ts`, `testedUsers` (diff l.190-196).** `const [layer, feature] = path.split("/")` peut donner `feature` ou `layer` `undefined` pour un chemin à un seul segment. Le filtre `t.layer === layer && t.feature === feature` peut alors faire correspondre des `undefined` à tort.
   - Correction : ignorer le chemin si `feature` est `undefined`.

8. **`packages/core/src/generate.ts`, `upstreamCount` (diff l.203-211).** Le motif `LIKE` n'échappe ni `_` ni `%` dans le chemin, et `c.split(" ")[0]!.replace("*", "%")` ne remplace que la première `*`. Le `!` masque aussi un `undefined` possible.
   - Correction : échapper les caractères spéciaux avec `ESCAPE`, utiliser `replaceAll`, et ne pas forcer le type avec `!`.
   - Une requête `COUNT` est exécutée par préfixe (N+1). Une seule requête avec `OR` suffirait.

9. **`packages/core/src/generate.ts`, `render` (diff l.224-228).** `description:` est écrit en YAML sans guillemets. Si `title` ou `summary` contient `:`, `#` ou un guillemet, le frontmatter est invalide.
   - Correction : sérialiser la valeur avec `JSON.stringify`.
   - Le texte `C:\\src` est codé en dur dans la description.

10. **`packages/core/src/generate.ts`, signature de `generate` (diff l.257-262).** Elle n'a pas de type de retour alors que `GenerateResult` est exporté juste au-dessus. Le défaut `join(homedir(), ".claude", "skills")` écrit hors dépôt par défaut.
    - Correction : annoter `Promise<GenerateResult[]>` et rendre `skillsRoot` explicite.

11. **Les deux fichiers, formatage.** Le diff n'a pas de newline final (`\ No newline at end of file` côté `generate.ts`). Le style n'est pas homogène : `bun fmt` laisse des chaînes à apostrophes et des lignes de plus de 100 caractères, comme le template `description:` (l.228 du diff) et la chaîne de `whenToUse`. Il n'y a pas de configuration de formateur visible dans le diff.
    - Correction : ajouter un `.editorconfig` ou une config de formateur versionnée, et ajouter le newline final.

**Absence de tests.** Aucun test ne couvre `generate`, `render` ou `testedUsers`, alors que ce code produit des skills publiés.
