**Défauts**

1. **`packages/ai-os/src/brain/cli.ts`, `sync()`, écriture de `settings.json` agy.** `readJson(gs)` fournit `g`, puis `trustedWorkspaces` est filtré avec `existsSync(w)` et `w.length > 3`. Le filtre `length > 3` supprime `C:\` (3 caractères), ce qui est voulu. Mais le filtre supprime aussi tout chemin valide mais absent (disque réseau déconnecté, chemin UNC lent), et la perte est silencieuse. Correction : journaliser les entrées retirées, ou n'écarter que les doublons et les chemins absents depuis longtemps.

2. **`cli.ts`, `sync()`, `g.trustedWorkspaces`.** `new Set` ne déduplique pas les chemins qui diffèrent par la casse ou le séparateur (`C:\src` et `c:/src`). Sous Windows, le doc local constate déjà 70 entrées avec doublons. Correction : normaliser avant le `Set`, avec `path.resolve` puis `toLowerCase()`.

3. **`cli.ts`, `sync()`, `hooks.json`.** Le doc `agy.md` constate que le hook pre-tool-guard est placé dans `~/.gemini/antigravity-cli/hooks.json`, alors que le chemin partagé est `~/.gemini/config/hooks.json`. Le commit documente ce défaut mais ne le corrige pas. Correction : écrire ou migrer vers `~/.gemini/config/hooks.json`, et vérifier le matcher `run_command|write_file|edit_file` contre les noms d'outils actuels.

4. **`cli.ts`, `sync()`, `mcp_config.json`.** Le doc relève la coexistence du fichier legacy (`antigravity-cli/`) et du fichier courant (`config/`). Le code ne traite pas ce cas. Correction : écrire dans `~/.gemini/config/mcp_config.json` seulement, et signaler ou purger le legacy.

5. **`cli.ts`, `sync()`, `g.artifactReviewPolicy = "always-proceed"`.** C'est cohérent avec le doc, mais `allowNonWorkspaceAccess = true` combiné à `always-proceed` et à `trustedWorkspaces` ajoute des permissions larges sans garde. Le doc précise que `always-proceed` n'auto-approuve plus les écritures hors workspace. Ajouter `allowNonWorkspaceAccess` est donc cohérent, mais rien ne le teste. Correction : ajouter un test qui lit le `settings.json` produit et vérifie les valeurs attendues.

6. **`cli.ts`, `absorb()`, boucle `roots`.** Les dossiers `antigravity-cli/brain` et `antigravity-cli/conversations` sont parcourus sans filtre de taille ni de type. Le filtre `memory` ne protège pas ces racines, et le code lit avec `statSync(p)` des fichiers qui peuvent être binaires ou volumineux. Correction : filtrer par extension et par taille avant lecture, et gérer l'exception de `statSync` si le fichier disparaît entre `walk` et `stat`.

7. **`cli.ts`, `absorb()`, double base `conversation_summaries.db`.** Les deux chemins (`antigravity`, `antigravity-cli`) sont lus avec la même requête. Si les deux contiennent la même conversation, les lignes sont insérées en double. Correction : clé de déduplication par identifiant de conversation, ou source indiquée dans la clé.

8. **`CLAUDE.md`, lignes ajoutées `@AGENTS.md` et `@.agents/SOUL.md`.** Les imports `@` sont relatifs au fichier qui les contient. C'est correct ici, mais l'import duplique le contexte déjà référencé par le lien Markdown du paragraphe précédent (même contenu chargé, plus de tokens). Je n'ai pas vérifié si `AGENTS.md` importe lui-même `CLAUDE.md`, ce qui créerait une boucle. Correction : supprimer le lien redondant du paragraphe ou la ligne d'import, et contrôler l'absence de boucle.
