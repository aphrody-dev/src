**Défauts vérifiables**

1. **`upstream-sync.yml`, étape « Report sync failures »**
   - **Problème :** `continue-on-error: true` rend `steps.sync.outcome == 'failure'` vrai, donc l'étape finale fait échouer le run. Mais l'étape « Regenerate snapshot » n'a pas de `if: always()`, ni de `if` du tout.
   - **Condition d'échec :** si `sync` plante avant la fin, le snapshot est quand même régénéré, car `continue-on-error` empêche l'arrêt du job. Cette partie est correcte.
   - **Défaut réel :** `sync.conclusion` vaut `success` alors que `outcome` vaut `failure`. L'ordre est donc correct, mais fragile.
   - **Correction :** déclarer explicitement `if: always() && steps.sync.outcome == 'failure'` sur le rapport.

2. **`upstream-sync.yml`, étape « Sync forks with upstream » (`GH_TOKEN: ${{ secrets.APHRODY_DEPLOY_TOKEN }}`)**
   - **Problème :** le repli sur `github.token` a été retiré. Si le secret est absent, `gh` échoue pour chaque fork. Les échecs sont comptés un par un et le message d'erreur est masqué par `tail -1`.
   - **Correction :** ajouter une vérification en tête d'étape : `test -n "$GH_TOKEN" || { echo "::error::APHRODY_DEPLOY_TOKEN missing"; exit 1; }`.

3. **`upstream-sync.yml`, boucle `while read -r up`**
   - **Problème :** `$fail` est modifié dans la boucle. La redirection `< "$list"` évite le sous-shell, donc la valeur est conservée, c'est correct.
   - **Défaut réel :** `echo "failures=$fail" >> "$GITHUB_STEP_SUMMARY"` écrit une ligne brute dans le résumé, sans titre ni liste des forks en échec.
   - **Correction :** accumuler les noms des forks en échec et les écrire en Markdown dans le résumé.

4. **`upstream-sync.yml`, `grep -E '^(EpicGames|bevyengine|...)/' ... | cut -d' ' -f1`**
   - **Problème :** le format de `forks.txt` n'est pas vérifié. Un séparateur tabulation ou plusieurs espaces casse le `cut`.
   - **Correction :** `awk '{print $1}'`.

5. **`upstream-sync.yml`, `bun-version: 1.4.4`**
   - **Problème :** la version épinglée n'est pas sourcée. L'action `oven-sh/setup-bun@v2` n'est pas épinglée par SHA. `actions/checkout@v7` est dans le même cas.
   - **Correction :** épingler les actions par SHA de commit et citer la source de la version de Bun dans le commit.

6. **`upstream-sync.yml`, étape « Regenerate snapshot », fin de l'étape**
   - **Problème :** `git pull --rebase origin main` puis `git push origin HEAD:main` n'ont pas de nouvelle tentative. Deux exécutions concurrentes peuvent entrer en conflit sur `snapshot.json`.
   - **Correction :** ajouter un bloc `concurrency:` au workflow, avec `cancel-in-progress: false`.

7. **`upstream-recon.ts`, `gql`, après `if (!res.ok || !body.data || body.errors?.length)`**
   - **Problème :** le message d'erreur est « GraphQL ${status}: undefined » quand `errors` est absent.
   - **Autre défaut :** l'erreur GraphQL partielle devient fatale. Un dépôt privé ou inaccessible dans la liste COMMUNITY fait donc échouer tout le snapshot.
   - **Correction :** `?? text.slice(0, 200)` pour le message. Pour les erreurs partielles, soit les ignorer pour `NOT_FOUND`, soit lister explicitement les dépôts concernés.

8. **`upstream-recon.ts`, écriture atomique**
   - **Problème :** `Bun.write(`${out}.tmp`)` puis `rename`. Si `out` est relatif et que `.tmp` persiste après un crash, le fichier reste dans le dépôt, car il n'est pas dans `.gitignore`. Le script ne nettoie rien en cas d'erreur.
   - **Correction :** utiliser `RUNNER_TEMP`, ou `try/finally` avec `unlink`, ou ajouter `*.tmp` au `.gitignore`.

9. **`upstream-recon.ts`, `localeCompare`**
   - **Problème :** le tri dépend de la locale du runner. Il n'est pas déterministe d'un environnement à l'autre, ce qui contredit l'objectif « instantané trié, sans horodatage ».
   - **Correction :** `a.repo < b.repo ? -1 : a.repo > b.repo ? 1 : 0`, ou `localeCompare(b.repo, "en")`.

10. **`upstream-recon.ts`, `process.env.GITHUB_TOKEN || process.env.GH_TOKEN`**
