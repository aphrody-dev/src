**Défauts de correction**

1. **L235 : `#` perdu dans un `select` imbriqué dans un `plural`.** `self.nodes(true, kind == "plural")` donne `in_plural=false` au corps d'un `select`. Le `#` y est donc lu comme du texte alors que `render` (L333) propage bien `pound`. En ICU, `#` dans un `select` sous un `plural` désigne le nombre du `plural`. Correction : passer `in_plural || kind == "plural"`, avec `in_plural` en paramètre de `argument()`.
2. **L135 : `#` entre apostrophes non géré dans un `plural`.** Seuls `{` et `}` déclenchent le quoting, donc `'#'` garde ses apostrophes ou devient un `Pound`. Correction : accepter `Some('{' | '}' | '#')` quand `in_plural` est vrai.
3. **L135-150 : apostrophe de quoting jamais fermée acceptée en silence.** Le texte est consommé jusqu'à la fin sans erreur. Correction : retourner `self.err("unterminated quote")`.
4. **L270 : `plural_category` ignore le signe.** `n == 1.0` est faux pour `-1`, alors qu'`Intl.PluralRules` utilise la valeur absolue. Correction : appeler `n.abs()`.
5. **L270 : catégorie `many` absente pour `fr` et `es`.** CLDR renvoie `many` pour 1 000 000 et plus (`e=6`), donc la parité TypeScript casse sur les grands nombres. Correction : ajouter la règle, ou rejeter explicitement ces valeurs.
6. **L278 : `num_text` sature pour les valeurs extrêmes.** `v as i64` sature au-delà de 2^63. `inf` et `NaN` s'affichent « inf » / « NaN », contre « ∞ » / « NaN » côté Intl. Correction : traiter `!is_finite()` à part et borner l'usage de `as i64`.
7. **L54 : `From<i64>` perd en précision au-delà de 2^53.** Il manque `From` pour `String`, `i32`, `u32`, `u64` et `usize`, donc `.into()` ne marche pas pour ces types.
8. **L353-375 : `match_locale` en deux passes redondantes.** La première recherche sur `base` est subsumée par la seconde. `zh-TW` et `zh-Hant` retombent sur `zh-CN`, donc écriture traditionnelle vers simplifiée sans que ce soit documenté. Correction : une seule passe, et exclure les scripts `Hant`/`TW`/`HK` ou le documenter.
9. **L396 : `partial_cmp().unwrap()` fragile.** Pas de panic aujourd'hui, car `NaN > 0.0` est faux et le `NaN` est filtré. Le garde-fou dépend pourtant d'une ligne distante. Correction : utiliser `total_cmp` et borner `q` à `[0,1]` (actuellement `q=1e9` est accepté).
10. **L416 : doc inexacte.** « fallback to the base language » : `t_args` (L447) ne fait que `locale` puis `en`. La base est déjà résolue par `match_locale`, donc le commentaire est trompeur.
11. **L447 : erreur de syntaxe avalée.** `unwrap_or_else(|_| key.to_owned())` masque l'erreur. Si le message localisé est invalide, `en` n'est pas tenté. Correction : essayer `en` ensuite, et journaliser ou exposer l'erreur (`try_t`).

**Robustesse et performance** 12. **L34 : `expect("catalog JSON is valid")` panique à l'exécution.** Un JSON non plat (clé imbriquée) fait aussi paniquer. Correction : valider dans un test, ou retourner un `Result`. 13. **L234 et suivantes : récursion sans limite de profondeur.** `format_message` est `pub` et prend une source arbitraire, donc des `select` imbriqués provoquent un stack overflow. Correction : ajouter une profondeur maximale (par ex. 32). 14. **L345 : message reparsé à chaque appel.** `t_args` fait `parse` à chaque appel, sans cache des `Vec<Node>` par `(locale, clé)`. 15. **L298-299 : arms dupliqués dans `render`.** Les deux `Some(Arg::Num(v))` produisent le même résultat, donc le champ `number` ne sert à rien. Il y a aussi une divergence connue avec `Intl.NumberFormat` à partir de 1000 (le séparateur de milliers manque), documentée en en-tête mais sans garde-fou. Correction : supprimer l'arm mort, et soit grouper, soit refuser les valeurs de 1000 et plus dans `number`. 16. **L15-22 : `include_str!` avec `../../../` hors du crate.** `cargo package` et `cargo publish` échouent, et la dépendance à `packages/` n'est pas déclarée dans `DEPS.rules` (qui ne contient que `layer = 1`). Même chose dans `tests/shared.rs` L7. Correction : `build.rs` ou répertoire de données dans le crate, avec `cargo:rerun-if-changed`.

**Tests** 17. **`tests/shared.rs` L44 : `every_message_parses` appelle `format_message(v, l, &[])`.** Le parse et le rendu sont couverts, mais sans arguments. Les branches plural, select et `#` ne sont pas rendues. 18. **`tests/shared.rs` L67-73 : couverture insuffisante.** Aucun test pour `fr` avec 0 et 1,5, `ja`/`zh` (toujours `other`), `-1`, les `select` imbriqués (défaut 1), `'#'` quoté (défaut 2), les valeurs de 1000 et plus, ni les quotes non fermées. 19. **`tests/shared.rs` L26 : le message d'assertion n'indique ni clé ni locale.** Il n'affiche que l'objet JSON complet, et `got` n'apparaît pas dans le message (il figure déjà via `assert_eq!`). Correction : utiliser `"{} / {}"` avec la locale et la clé. 20. **`tests/shared.rs` L1-3 : le test de parité se limite aux fixtures partagées.** Rien n'assure que le fichier de fixtures couvre les cinq locales. Correction : asserter que l'ensemble des `locale` des fixtures égale `LOCALES`.
