**Note : 12/20**

Les numéros de ligne sont ceux des fichiers après le commit, pas ceux du diff. Je n'ai pas exécuté le code ni les tests : tout vient de la lecture du diff.

**Bloquants**

1. `i18n.ts` L33 : `catalogs[l]?.[key]` et `k in source/cat` (`check.ts` L30, L36 ; `cli.ts` L94) lisent le prototype d'`Object`. Pour `t("constructor")` ou `t("toString")`, `find` renvoie une fonction et `formatMessage` plante. Correction : `Object.hasOwn`, ou des catalogues construits avec `Map` ou `Object.create(null)`.
2. `i18n.ts` L45 : `t()` lève `MessageSyntaxError` si un catalogue est invalide. Il devrait attraper l'erreur et retomber sur `en`, puis sur la clé, comme le promet la doc L10.
3. `negotiate.ts` L26-33 : `matchLocale` rabat `zh-TW`, `zh-HK` et `zh-Hant` sur `zh-CN`, donc sur du chinois simplifié. Le test `i18n.test.ts` L68 fige ce comportement. Correction : comparer le script (`Intl.Locale.maximize()`), et ne faire la correspondance sur la langue seule que si le script est compatible. Sinon retomber sur `en`.
4. `icu.ts` L144 : `parseNodes(true, kind === "plural")` remet `inPlural` à faux dans un `select` imbriqué dans un `plural`. Le `#` y est donc lu comme du texte, alors que `render` L174 gère déjà `pound`. Correction : transmettre `inPlural` aux `select`.
5. `fr.json` L16 et `es.json` L16 : les messages pluriels n'ont pas la catégorie CLDR `many`. Pour un million de fichiers, on obtient « 1000000 archivos » au lieu de « 1 millón de archivos ». `check` ne vérifie pas les catégories de pluriel requises par locale. Correction : ajouter `many` et valider `Intl.PluralRules(l).resolvedOptions().pluralCategories`.

**Majeurs**

6. `i18n.ts` L52 et `cli.ts` L13 : `new URL(...).pathname` renvoie `/C:/…` sous Windows et laisse les `%20` encodés. `cli.ts` ne corrige que la lettre de lecteur, `loadCatalogs` ne corrige rien. Correction : `fileURLToPath`.
7. `check.ts` L19-20 : le catalogue source n'est jamais validé. `safeArgs` avale l'erreur de syntaxe et renvoie `[]`, ce qui fait échouer tous les `placeholders` des autres locales. Le catalogue `en` devrait lui aussi apparaître dans le rapport.
8. `check.ts` L45 : le commentaire L44 parle de « subset » mais le code exige l'égalité stricte des noms d'arguments. Un locale qui omet légitimement un argument est donc rejeté. Il faut aligner le code sur le commentaire, ou l'inverse.
9. `check.ts` L36-42 et `cli.ts` L27 : `as Catalog` ne vérifie rien. Une valeur non chaîne produit un `TypeError`, que `check.ts` relance. Un JSON invalide plante le CLI sans message. Correction : valider que le contenu est un objet plat de chaînes, avec un rapport d'erreur propre.
10. `cli.ts` L33-38 : `Bun.file().exists()` sert à tester si le chemin est un fichier, et la variable s'appelle `st`. Un chemin inexistant déclenche un `ENOENT` non géré. Un fichier passé en argument est ajouté sans filtre d'extension. Correction : `stat` avec `isFile()`, plus un message d'erreur.
11. `cli.ts` L87 : `.catch(() => ({}))` masque un dossier de catalogues absent. `extract` sort alors en code 0 sans vérifier les clés inconnues.
12. `check.ts` L66 : la regex `t(` extrait aussi les clés de `foo.t(...)`, celles des commentaires, et les gabarits `` `a${b}` `` (clé non statique). L'échappement `\\.` est conservé tel quel dans la clé.
13. `icu.ts` L56-79 : l'apostrophe devant `{` ou `}` ouvre une citation. Un français courant comme `d'{name}` ou `l'{x}` avale donc le placeholder sans erreur. Ni le parseur ni `check` ne le signalent. Le `#` n'est pas citable dans un `plural`.
