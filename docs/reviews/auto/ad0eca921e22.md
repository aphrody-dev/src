**Défauts vérifiables**

1. **`cli.ts` L284-288, restore : la protection contre la sortie du dossier home a été supprimée.**
   - Le commit annonce « restore bounded by path.relative », mais le diff retire le `startsWith(H + sep)` sans rien le remplaçant.
   - Aucun `relative` n'a été ajouté. Une ligne `blobs.path` du type `../../x` ou un chemin absolu d'une autre lettre de lecteur est donc écrite hors home. `mkdirSync` recursive aggrave le cas.
   - Correction : `const rel = relative(H, out); if (rel.startsWith("..") || isAbsolute(rel)) throw …` avant le `mkdirSync`.
   - La doc `.md` affirme un correctif qui n'existe pas dans le code.

2. **`cli.ts` L209-210 : la revérification avant suppression est incomplète.**
   - Elle compare `mtimeMs` et `size`. Une réécriture de même taille avec `mtime` restauré passe, et la fenêtre TOCTOU reste ouverte entre `statSync` et `rmSync`.
   - `statSync(p)` lève une exception si le fichier a disparu entre-temps, ce qui interrompt toute la boucle.
   - Correction : entourer d'un `try/catch`, ou relire le fichier et comparer les octets juste avant le `rmSync`.

3. **`cli.ts` L199, L217 : `zstd` niveau 19 sur des fichiers entiers en RAM, avec un `VACUUM` global.**
   - Le commit liste ce point comme « Open », donc non corrigé.
   - Correction : utiliser un niveau 3 à 9, ou un flux. Remplacer `VACUUM` par `PRAGMA incremental_vacuum`, ou le déclencher seulement au-delà d'un seuil.

4. **`cli.ts` L205-208 : la vérification relit la base mais ne la valide pas.**

   - Correction : `blobs.transaction(...)` par fichier. Le `rmSync` ne doit venir qu'après le commit.

5. **`cli.ts` L37-39, `--days` : le regex n'accepte pas `1e3`, `+1` ni `.5`.** Le comportement est acceptable, mais `.5` est refusé sans message explicite. Le message d'erreur est correct.

6. **`cli.ts` L288 : `utimesSync(r.mtime / 1000)`.** `mtime` a été arrondi à la milliseconde à l'écriture, donc la précision est perdue. Le test tolère `< 2 s`, ce qui est trop lâche pour détecter une régression.
