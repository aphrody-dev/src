1. **`play-launcher.ts` L93-99 : `await startStage(...)` avant le premier affichage.** Le chargement des matériaux WebGPU bloque le lanceur. Pendant ce temps, `#msg` est masqué par le CSS et le bouton Start n'existe pas à l'écran. Il faut afficher le lanceur tout de suite, puis initialiser la scène sans bloquer.
2. **`play-launcher.ts` L100 : `window.__stage = handle?.stats ?? null`.** `stats` est capturé au démarrage. Si c'est un objet muté, ça va. Si c'est une valeur, elle est figée. À vérifier, ou exposer un getter.
3. **`play-launcher.ts` L82-83 : `unlock` avec `{ once: true }`, séparément sur `pointerdown` et `keydown`.** Le premier geste qui échoue (contexte `suspended`) n'est pas retenté. Il n'y a aucun écouteur pour la manette. `onFocus` rappelle `unlock()`, mais seulement après un geste. Il faut un `unlock` répété jusqu'à `ctx.state === "running"`, et retirer l'autre écouteur ensuite.
4. **`play-launcher.ts` L112 : Start n'écoute que `click`.** La description annonce « Enter, click or gamepad A ». Entrée sur un bouton focalisé déclenche bien `click`. Le gamepad A ne passe que si `startStage` appelle `.click()` sur l'élément, ce que le diff ne montre pas. Aucun test ne le couvre.
5. **`play-launcher.ts` L115-116 : pas de `finally`.** Si `destroy()` lève une exception, le lanceur reste visible. De plus, `done` n'est jamais rejeté si la scène plante après le démarrage. Les écouteurs `pointerdown` et `keydown` ne sont jamais retirés quand `{ once }` n'a pas été consommé.
6. **`play-launcher.ts` L76 : `has("autostart")` accepte `?autostart=0`.** Le paramètre vaut « présent », pas `1`. Il faut comparer à `"1"`.
7. **`play.ts` L39-40 : `await launcher()` bloque `main()`.** Le jeu ne charge pas son wasm pendant que le menu est affiché. Il faut lancer le chargement en parallèle et n'attendre que le démarrage.

11. **`sound.ts` L162 : gains codés en dur.** Le volume n'est pas configurable et le gain n'est pas rampé, donc le clic peut craquer.
