## Défauts vérifiables

1. **Les résultats Rust sont attribués au mauvais type** (`packages/assets/src/test.ts`, l.1783-1802). `byId.get(j.id)` ne retrouve jamais les lignes dont l'id est inconnu, et `|| "audio"` les range alors en audio. Les lignes SVG, font et craft en sont aussi affectées, et le `.mp4` peut être mal rangé. Le tableau de `ASSET-TESTS.md` en dépend : audio affiche 74 contrôles pour 37 OGG (37 tv-ffmpeg + 37 sha256), et aucune ligne ttf-parser n'apparaît.
   - Correction : écrire le champ `type` dans le JSON côté Rust, ou rejeter et signaler toute ligne dont l'id est inconnu.

2. **`craft-formats` répond « svg signature » sans rien décoder** (`crates/asset-test/src/main.rs`, l.933-936). `craft()` renvoie `Ok` dès que la signature est un SVG. Les 56 lignes `craft-formats` du rapport, à 0,001 ms, ne valident donc rien. Ce n'est pas un test de décodeur, alors que le commit prétend valider avec craft-libs.
   - Correction : retirer cette ligne, ou appeler un vrai parseur.

3. **Les images ne sont presque pas testées.** Dans `ASSET-TESTS.md` l.1114, 6110 des 6128 images sont « skipped » et seules 18 sont validées. Les 249 modèles sur 337 non testés sont dans le même cas (l.1115). La note l.1101 prétend que les lignes sautées sont « not fetched, not passes ». Le titre « validation récursive de la bibliothèque » est pourtant faux, et `--strict` ne rend pas les entrées manquantes bloquantes.
   - Correction : en mode `--strict`, compter chaque `skipped` comme un échec. Le workflow lance bien `fetch --remote`, mais rien ne vérifie que le fetch a réussi.

4. **Les sauts côté Rust sont invisibles** (`main.rs`, l.1047-1050). Si `std::fs::read` échoue, le `continue` n'émet aucune ligne.
   - Correction : émettre `ok:false` pour que `--strict` détecte le manque.

5. **Le test Bevy « headless » peut ne pas l'être** (`main.rs`, l.989-1003).
   - `DefaultPlugins` charge aussi la fenêtre et l'audio.
   - `backends: None` n'est pas garanti de désactiver la création du GPU dans Bevy 0.20, que je n'ai pas pu vérifier.
   - Les 20 000 itérations avec `sleep(1ms)` donnent un délai d'environ 20 s ou plus, sans rapport avec la taille du fichier.
   - Un `panic` dans `app.update()` est attrapé par `catch_unwind` et devient « panic », sans détail.
   - Correction : utiliser `MinimalPlugins` avec `AssetPlugin` et `GltfPlugin`, et inclure le message de panic dans le détail.

6. **Le fingerprint peut rater un changement de décodeur** (`retest.ts`, l.1352-1363).
   - Le découpage par `"\n\n"` suppose des stanzas séparées par une ligne vide. Cargo.lock le fait, mais pas en CRLF.
   - Le test à la ligne 2013 ne couvre qu'un seul cas.
   - Le fingerprint lit des chemins `third_party/*` dans `src.lock.json`, sans preuve qu'ils existent dans `repositories`. Si la clé est absente, la valeur `-` rend le déclencheur inopérant sans aucun avertissement.
   - Correction : valider que chaque pin existe, sinon échouer.

7. **`retest()` écrit le fingerprint même si des résultats sont ignorés** (l.1398). Le stamp est enregistré quand `code === 0`. Or `testCommand` renvoie 0 avec 6110 sauts, donc un test quasi vide fige l'empreinte.
   - Correction : exiger zéro `skipped` pour écrire le stamp.

8. **Mauvais regroupement du type `manifest`.** Les fichiers non listés (`unlisted:`) ont `type` calculé par `classify`, ce qui est correct. Les échecs de l'étape « rust-stage » ont en revanche le type `manifest`, et `summarize` les range dans une ligne « manifest » qu'`ASSET-TESTS.md` ne montre pas.

9. **`--type` mal géré** (`test.ts`, l.1762-1767). Quand plusieurs types sont passés, `o.types?.length === 1` est faux et `--type` n'est pas transmis à Rust. Le Rust exécute alors tout puis filtre côté TS, ce qui est lent. Côté Rust, `--type image` n'accepte que `craft`.

10. **Détection de chemin fragile** (`test.ts`, l.1674).
    - `f.startsWith(join(lib, "remote"))` exclut aussi un dossier `remote-foo`.
    - `/^manifest/` exclut tout fichier nommé `manifest*`, même un asset.
    - Correction : comparer avec `join(lib, "remote") + sep`, et réutiliser la regex de `manifestPaths`.

11. **Faux sentiment de sécurité sur le HDR** (l.1520-1535).
    - Le payload n'est comparé qu'à `min(w*h, 4096)` octets.
    - La seule vérification est la présence de `FORMAT=32-bit_rle_rgbe`.
    - Les 642 HDRI « passent » sans décodage RLE.
    - Correction : décoder avec un vrai lecteur, ou nommer la validation « en-tête seulement ». C'est déjà le cas dans le nom `radiance-header`, mais pas dans le titre du rapport.

12. **Bug de lecture mémoire en TS** (l.1707). `Bun.file(...).arrayBuffer()` charge entièrement en RAM les fichiers de 1 Go, et chaque fichier est lu même quand seul `existsSync` est nécessaire (les HDRI pèsent 1,04 Go au total). C'est aussi mal fait côté Rust (`std::fs::read` sur chaque asset avant filtrage par type).

13. **Fuite des chemins dans `khronos`** (l.1572-1577). `join(dir, decodeURI(uri))` accepte `../` : un glTF malveillant lit n'importe quel fichier. C'est un test de bibliothèque interne, mais l'`externalResourceFunction` devrait vérifier le préfixe.

14. **`fileFor` et `load_manifest` divergent.** En Rust, une entrée remote sans `ASSETS_STORE` retombe sur `lib` (`store.clone().unwrap_or_else(...)`). En TS, `ASSETS_STORE` absent donne aussi `lib`, mais `storage` est lu avec `s("storage")` qui exige une chaîne. Les deux se comportent pareil aujourd'hui, mais la logique est dupliquée.

15. **Workflow `assets.yml`.**
    - L.74 : `actions/checkout@v7` et l.99 `actions/upload-artifact@v5` : versions à vérifier sur les releases réelles.
    - L.90 : le `cd` n'est pas fait vers `SRC_ROOT`, et `asset-test .` suppose le répertoire de travail.
    - `ASSETS_STORE` n'est pas déclaré dans le fingerprint.
    - `cancel-in-progress: false` sur un job de 90 min peut empiler les runs du cron quotidien.

16. **Suppressions sans lien avec le commit.** Le diff supprime `crates/aphrody-i18n` (452 lignes plus tests), `infra/fleet/workers/r2-site/*`, `apps/aphrody-app/wrangler.toml`, et ajoute `packages/i18n` et `packages/site` au `bun.lock`. Rien de cela n'est mentionné dans le message de commit. La suppression du worker R2 retire cinq déploiements Cloudflare (routes custom_domain) sans remplaçant visible dans le diff. Il faut séparer ces changements ou les documenter.

17. **Tests insuffisants.** `library.test.ts` exclut `audio`, `svg` et `font`, donc le chemin Rust n'a aucun test d'intégration. `retest()`, `runRust` et le parsing JSON ne sont pas testés. Le test unitaire du fingerprint ne couvre pas la stanza en début de fichier.

18. **Dépendance non épinglée.** `gltf = "1.4.1"` et `ttf-parser = "0.25.1"` sont dans `Cargo.toml` hors `workspace`, alors que le reste utilise `.workspace = true`. Le fingerprint lit `Cargo.lock`, donc c'est cohérent, mais ça contredit la politique du dépôt.

19. **Rapport incohérent.** `ASSET-TESTS.md` annonce 8180 entrées et 137 entrées côté Rust. Les totaux affichés (74+748+722+6128+337+168 = 8177) ne sont pas égaux à 8180. Le tableau « Validators » compte aussi 6439 lignes `present`, à 0,000 ms, qui gonflent les statistiques.

## Verdict
Le but déclaré est une validation récursive de toute la bibliothèque, mais le rapport montre que ce n'est pas le cas : 6110 images sautées et 249 modèles sur 337 non testés, alors que ces chiffres devraient bloquer le commit. À corriger en priorité : les points 1 à 4 et 7. Les points 5 et 16 viennent ensuite.
