## Défauts

1. **`cli.ts`, restore, garde de chemin : contournement par préfixe.**
   - `out.startsWith(H + sep)` suppose que `H` est normalisé. `H` vient de `homedir()` et n'est pas passé par `resolve`.
   - Si `H` se termine par `sep` ou diffère par la casse (Windows, insensible à la casse), la garde échoue à tort ou laisse passer.
   - Correction : `const root = resolve(H)`, puis comparer avec `relative(root, out)`. Refuser si le résultat commence par `..` ou si `isAbsolute(...)` est vrai. Comparer en minuscules sous win32.

2. **`cli.ts`, restore, requête SQL : séparateur incohérent.**
   - Les chemins sont stockés avec `relative(H, p)`, donc avec `\` sous Windows.
   - L'argument `path` est passé tel quel dans `path = ?`. Une entrée avec `/` ne correspondra à rien.
   - Le préfixe `${path}${sep}%` n'est pas normalisé non plus, ni absolu contre relatif.
   - L'ancienne version convertissait `/` en `\`, et le nouveau code a supprimé cette conversion.
   - Correction : normaliser avec `relative(H, resolve(path))` avant la requête.

3. **`cli.ts`, restore : `ESCAPE '!'` appliqué au préfixe seulement.**
   - Le `!` du chemin est bien échappé. Mais `path = ?` utilise le chemin brut, et c'est correct.
   - Point à confirmer : le caractère `%` ajouté après `sep` n'est pas échappé, ce qui est voulu.
   - Aucun test ne le couvre.

4. **`cli.ts`, restore : lecture seule et pas de vérification d'intégrité.**
   - La base est ouverte avec `readonly: true`, mais le mode WAL a été activé à l'écriture. Une base WAL en lecture seule exige que les fichiers `-wal` et `-shm` soient accessibles.
   - La décompression n'est pas protégée par un `try/catch`. Un blob corrompu interrompt tout le restore sans rapport sur les fichiers déjà restaurés.
   - Il n'y a aucun contrôle de taille contre la colonne `size`.
   - Correction : comparer `decompressed.length` à `r.size`, et attraper les erreurs par ligne.

5. **`cli.ts`, restore : `utimesSync` avec `mtime / 1000`.**
   - `mtime` est stocké en millisecondes arrondies. La division donne des secondes flottantes, ce qui est acceptable.
   - Mais `Bun.write` crée les répertoires parents, et leurs mtimes ne sont pas restaurés. C'est mineur.

6. **`cli.ts`, absorb, vérification avant suppression : hash non cryptographique.**
   - `Bun.hash` est wyhash 64 bits. Ce n'est pas un hash d'intégrité.
   - Correction : comparer directement les octets (`Buffer.compare`) ou utiliser `Bun.CryptoHasher("sha256")`.
   - Cette vérification ne protège pas contre une corruption survenue après le `SELECT`, mais elle reste suffisante pour le cas visé.

7. **`cli.ts`, absorb : fichier modifié entre lecture et suppression.**
   - `st` est lu avant `Bun.file(p).bytes()`, puis `rmSync(p)` supprime sans revérifier.
   - Un fichier réécrit entre les deux perd des données. C'est la situation typique d'une session live.
   - Correction : refaire `statSync` juste avant `rmSync` et sauter si `mtimeMs` ou `size` ont changé.

8. **`cli.ts`, absorb : l'erreur de vérification interrompt toute la boucle.**
   - Un `throw` arrête le lot au premier fichier en échec, sans rapport ni poursuite.
   - Correction : journaliser, incrémenter un compteur d'échecs, passer au fichier suivant et fixer `exitCode`.

9. **`cli.ts`, absorb : transaction qui ne couvre qu'un `run`.**
   - `blobs.transaction(() => put.run(...))()` encapsule une seule instruction. C'est déjà atomique sans transaction explicite, donc cette enveloppe n'apporte rien.
   - La vraie atomicité à garantir est « insertion + vérification + suppression ». La vérification se fait hors de la transaction.
   - Correction : retirer l'enveloppe, ou la remplacer par un `BEGIN` ... `COMMIT` autour de la vérification, qui doit se faire dans la même connexion.
   - Avec `synchronous` par défaut en WAL, la durabilité n'est pas garantie après un crash. Mettre `PRAGMA synchronous=FULL` avant de supprimer.

10. **`cli.ts`, `--days` : validation partielle.**
    - `Number("")` vaut `0`, donc `--days ""` passe la validation et supprime tout ce qui est plus vieux que maintenant.
    - `--days 0` est lui aussi accepté et condamne tous les fichiers.
    - Correction : exiger `days > 0`, ou un flag explicite comme `--all` pour `0`. Rejeter une chaîne vide.
    - Le `throw` au niveau du module donne une trace de pile au lieu d'un message CLI propre.

11. **`cli.ts`, sync : `indexOf(END, b)` quand `b` vaut `-1`.**
    - Le cas est géré par `b >= 0`. Mais un `END` présent sans `BEGIN` ajoute un second bloc.
    - Un `BEGIN` sans `END` ajoute aussi un bloc, laissant l'ancien orphelin et dupliquant les directives.
    - Correction : traiter ces cas comme une erreur explicite.

12. **`cli.ts`, sync : écriture non atomique de `GEMINI.md`.**
    - L'écriture directe peut tronquer le fichier en cas d'interruption. Correction : écrire dans un fichier temporaire puis renommer.

13. **`justfile`, recettes `cf-plan` et `cf-proof` : hors sujet.**

    - Correction : les déplacer dans un commit distinct, ou vérifier leur présence avec `git ls-files infra/cloudflare`.

16. **Points laissés ouverts, tous graves.**

    - Chemin `MEMORY.md` codé en dur sur `C--src`.
    - Effets de bord au niveau du module, ce qui rend le code intestable et casse tout import.
    - Fichiers entiers chargés en RAM avec zstd niveau 19. Un transcript de plusieurs centaines de Mo peut faire échouer le processus.
    - Correction : compresser en flux, ou fixer un plafond de taille, et lever les effets de bord dans une fonction `main()`.
