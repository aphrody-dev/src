## Bloquants

1. **`crates/game/src/synth.rs:63` et `:126` (probable)** : le test `sounds_are_deterministic_and_bounded` échoue très probablement.
   - `wind_loop` multiplie un bruit filtré (écart-type ≈ 0,083) par `gust * 4,5`, avec `gust` jusqu'à 1,15. L'écart-type vaut alors ≈ 0,43 au pic.
   - Sur 2 s, soit 44 100 échantillons, des valeurs dépassent 1,0 avec une quasi-certitude.
   - `wav_bytes` écrête ensuite le signal, donc le vent audible sature aussi.
   - Correction : ramener le gain à environ 1,5, ou normaliser le signal par son pic. Faire passer le test réellement.

2. **`apps/aphrody/src/client/play.ts:32` et `:59`, `scripts/game-fps.ts:181-187` (certain)** : course entre le script de mesure et la page.
   - `window.__play` est exposé avec `gpu:false` dès le début, et `gpu` n'est mis à jour qu'après `await hasWebGpu()`.
   - Le script interroge toutes les 500 ms. S'il lit l'état dans cet intervalle, il sort avec « no adapter » à tort.
   - Correction : `gpu: boolean | null`, ou un champ `ready`, que le script attend.

3. **`.github/workflows/game.yml:71` (certain)** : le code de retour de la mesure est perdu.
   - `bun … | tee … || rc=$?` renvoie le code de `tee`. Le shell par défaut de GitHub Actions est `bash -e {0}`, sans `pipefail`.
   - `rc` vaut donc toujours 0 : les codes 1 (sous la cible) et 2 (non mesuré) ne sont jamais détectés.
   - Le défaut `--min-fps 0` est de toute façon utilisé, donc l'objectif des 120 fps n'est jamais testé.
   - Correction : `shell: bash` (qui active `pipefail`), ou rediriger vers un fichier au lieu d'un pipe, et passer `--min-fps`.

4. **`scripts/game-fps.ts:122` (certain)** : `notMeasured()` appelle `process.exit(2)` dans le `try`.
   - Le `finally` ne s'exécute pas : Chrome n'est pas tué et le profil temporaire n'est pas supprimé. Chaque exécution laisse un Chrome orphelin sur fr1.
   - Correction : lever une exception, ou mettre le nettoyage dans `try/finally` et sortir après.

5. **`scripts/game-fps.ts:144-154` (probable)** : Chrome ne démarre pas dans les conditions du CI.
   - Les agents tournent en root et il n'y a pas de `--no-sandbox`. Chrome refuse alors de démarrer en root.
   - Pour WebGPU sans GPU en headless, il manque aussi `--use-angle=vulkan` ou `--use-webgpu-adapter=swiftshader`.
   - Résultat : le step de mesure finit toujours en « not measured ».

6. **`crates/game/Cargo.toml:26` et `:62`, commit entier (certain)** : le commit n'ajoute ni `Cargo.lock` ni modification du `Cargo.toml` racine.
   - Il ajoute pourtant un arbre de dépendances Bevy et utilise `bevy = { workspace = true }` et `console_error_panic_hook = { workspace = true }`.
   - Soit le workspace les déclare déjà, soit la compilation échoue. L'étape wasm-bindgen (`game.yml:50`) lit la version dans `cargo metadata`, qui modifierait le lockfile sans `--locked`.
   - Correction : committer `Cargo.lock`, vérifier la déclaration workspace avec `default-features = false` (sinon le commentaire « tout est listé explicitement » est faux), et ajouter `--locked` à tous les builds.

7. **`apps/aphrody/build.ts:33` et `:140-141` (certain)** : le commit introduit sans mention `import { buildImmersive }` et un build « Immersive stage ».
   - Ce n'est pas dans le message du commit. `src/immersive/build` n'est pas dans la liste des fichiers modifiés.
   - Soit le fichier existe déjà et c'est du hors-sujet, soit le build casse.
   - Correction : retirer ces lignes ou en faire un commit séparé.

## Majeurs

8. **`apps/aphrody/src/play/page.ts:20-24` (probable)** : l'URL des assets du jeu est relative.
   - Bevy charge `assets/models/explorer.glb`, résolu par rapport au document.
   - `server.ts:237` et `scripts/game-fps.ts` servent `/play` sans slash final : la requête part alors vers `/assets/…` (404), et le personnage ne se charge pas.
   - Correction : `<base href="/play/">`, ou `AssetPlugin { file_path: "/play/assets" }`, ou une redirection de `/play` vers `/play/`.

9. **`crates/game/src/player.rs:104-121` (certain)** : `grounded` ne repasse jamais à `false` quand le joueur quitte un bord.
   - Pendant une chute, il peut donc sauter en l'air, garde l'accélération au sol de 14, et déclenche des `Footstep`.
   - Il n'y a pas non plus de limite de pente sur le relief jusqu'à 90 m.
   - Correction : `grounded = tf.y <= ground + ε` à chaque frame, avant le saut.

10. **`crates/game/src/daynight.rs:85-86` (certain)** : le commentaire « lève à l'est (+x) » est faux.
    - La rotation autour de X place la course du soleil dans le plan YZ : il se lève en +z et se couche en −z. Le `from_rotation_y(0.5)` ne donne qu'un léger décalage.
    - Correction : appliquer d'abord la rotation autour de Y (azimut), puis celle autour de X ; ou corriger le commentaire.

11. **`crates/game/src/procgen.rs:218`, `apps/aphrody/src/play/page.ts:30`, `crates/game/assets/ui/crosshair.svg` (certain)**

12. **`crates/game/src/terrain.rs:73` et `:66-72` (certain)** : coût et absence de LOD.
    - 225 chunks de 2 048 triangles font ≈ 460 k triangles, plus 4 cascades d'ombre. Le terrain projette des ombres sur tout le rayon.

    - L'objectif de 120 fps (PARITY) est irréaliste sans LOD, culling ou limite de distance d'ombre.
