# Revue Gemini 6fbba4e35805

- Commit : ay flat : un flat.toml par fork (--fork, --manifest), licence SPDX par module contre la liste deny.toml, second manifeste diffutils (bre.rs, MIT OR Apache-2.0)
- Moteur : antigravity (38208 ms)

**Note : 12/20**

Revue faite sur le diff seul. Je n'ai pas exécuté les tests ni consulté `deny.toml`. Les numéros de ligne sont ceux du fichier de diff `prompt.md`.

**Défauts**

1. **`spdx_atom`, `sync.rs` l.335-341 : l'exception `WITH` est mal gérée.**
   - Un identifiant suivi de `WITH` n'est accepté que si la chaîne exacte `"X WITH Y"` figure dans la liste d'autorisation.
   - Si `deny.toml` autorise `Apache-2.0` et `LLVM-exception` séparément, une licence `Apache-2.0 WITH LLVM-exception` est refusée.
   - Le test l.466 ne couvre que le cas où la forme complète est déjà dans la liste.
   - Correction : parser l'identifiant et l'exception séparément, et suivre le format de `cargo-deny` (`allow` et `exceptions`).

2. **`spdx_allowed`, l.285-292 : les mots-clés SPDX sont sensibles à la casse, et les tests le contredisent.**
   - `OR`, `AND` et `WITH` ne sont reconnus qu'en majuscules, alors que `NOASSERTION` et `NONE` sont comparés sans casse.
   - `MIT or Apache-2.0` est donc rejeté comme « unexpected ».
   - L'erreur ne dit pas que la casse est en cause.
   - Correction : normaliser les opérateurs, ou ajouter un message explicite et un test.

3. **`spdx_atom`, l.341 : les identifiants ne sont pas validés.**
   - Le `+` d'une licence « or later » (`GPL-2.0+`) n'est pas géré.
   - `LicenseRef-*` et `DocumentRef-*` ne sont pas traités. Le test l.484 ne les rejette que parce qu'ils sont absents de la liste.
   - Correction : valider la grammaire de l'identifiant, ou documenter que seule la correspondance exacte est supportée.

4. **`flat.rs` l.90-92 : la licence du dépôt n'est jamais lue.**
   - `fork_license_file` ne vérifie que la présence d'un fichier `LICENSE*` et renvoie son nom, ignoré par `load`.
   - Aucun contrôle ne compare ce fichier à la licence déclarée dans `flat.toml`.
   - Pour diffutils, un fichier `LICENSE-MIT` seul passe alors que `flat.toml` déclare `MIT OR Apache-2.0`.
   - Correction : détecter la licence (SPDX ou texte) et la comparer, ou renommer la fonction et la documenter comme simple vérification de présence.

5. **`flat.rs` l.90 : la vérification de licence est silencieusement sautée sur un fork absent.**
   - `fork.join(".git").exists()` est faux pour un checkout sans `.git` (archive, sous-module non initialisé, worktree).
   - `ay flat check` répond alors OK sans avoir vérifié la licence du fork.
   - Correction : l'exiger en mode `--strict`, ou afficher un avertissement.

6. **`flat.rs` l.99-100 : le chemin de la racine est dupliqué.**
   - `run_flat` calcule `root`, puis `dirs` refait `unwrap_or_else(repo_root)` en lui passant `Some(root.clone())`.
   - Le paramètre `Option` de `dirs` est devenu inutile.
   - Correction : `dirs(root: &Path, …)`.

7. **`flat.rs` l.72-78 : chemins `--fork` / `--manifest` absolus mal traités.**
   - `root.join(abs)` ne casse pas Rust sous Windows, mais un chemin `\foo` ou `C:foo` produit un résultat incohérent.
   - Aucun test sur ce cas.
   - Correction : tester explicitement les chemins absolus.

8. **`flat.rs` l.75-76 : le nom du crate dérive de `fork.file_name()`.**
   - Avec `--fork third_party/diffutils/`, le nom est correct.
   - Avec `--fork .` ou `..`, `file_name()` renvoie `None` ou `".."`, donc `-flat/flat.toml`. L'erreur obtenue est trompeuse.
   - Correction : refuser un `name` vide.

9. **`flat.rs` l.130-141 : le test de la porte de licence est incomplet.**
   - Il charge tous les `crates/*/flat.toml` mais n'appelle pas `fork_license_file`.
   - Il ne vérifie pas non plus que `deny.toml` contient bien la licence du second manifeste.
   - Correction : ajouter l'assertion sur le fichier de licence du fork, ou le dire dans le nom du test.

10. **`flat.toml` (`bun-flat`) l.166-167 : changement de licence non justifié.**
    - `"MIT (HdrHistogram layout: CC0 1.0 or BSD-2-Clause)"` devient `"MIT"` pour passer la porte.
    - Cette note SPDX non conforme ne passait pas la porte, mais elle contenait une information de provenance.
    - Si le code Rust histogram dérive d'HdrHistogram, la mention CC0/BSD-2-Clause doit rester en commentaire ou en `LicenseRef`. L'attribution est perdue, ce qui est un risque de conformité.
    - Correction : commentaire dans `flat.toml` et `lib.rs`, ou `MIT AND BSD-2-Clause`.

11. **`diffutils-flat/Cargo.toml` : cohérence de licence et de lints.**
    - `[lints]` vide : le commentaire dit « the fork's lints apply upstream », mais `[lints]` sans `workspace = true` désactive simplement les lints du workspace.
    - La licence du crate (`MIT OR Apache-2.0`) n'est vérifiée par aucun test, ni contre `bre.rs`, ni contre `deny.toml`.
    - Correction : test de cohérence entre `Cargo.toml` et `flat.toml`.

12. **`bre.rs` : le code généré contient des tests inertes.**
    - `use pretty_assertions::assert_eq;` (l.834) figure dans le module `tests`, alors que `test = false` est positionné dans le `Cargo.toml` (l.536-537). Ce code n'est jamais compilé en test.
    - Les tests d'upstream (l.831-930) sont copiés dans le dépôt, sans garantie qu'ils passent.
    - Correction : retirer le module `#[cfg(test)]` à la génération, ou ajouter `pretty_assertions` en dev-dependency.

13. **`lib.rs` généré (diffutils, l.938-940) : texte incorrect.**
    - Le préambule dit « Leaf crates ... so `ay` links them without the fork checked out », mais `bre.rs` n'est pas un crate feuille : le module vient de `crate = "diffutils"`, le binaire principal du fork.
    - Aucune mention du `LICENSE-*` requis, malgré l'en-tête de `bre.rs` (« please view the LICENSE-* files »).
    - Le crate n'embarque pas les fichiers de licence, ce qui est un défaut de redistribution pour MIT et Apache-2.0.
    - Correction : copier `LICENSE-MIT` et `LICENSE-APACHE` dans `crates/diffutils-flat/`.

14. **`diffutils-flat/flat.toml` : `foreign_prefix` absent.**
    - Aucun contrôle des dépendances croisées pour ce fork. Si `bre.rs` appelle plus tard `crate::autre_module`, le code généré compile mal.
    - Correction : positionner `foreign_prefix` ou documenter son absence.

15. **`lib_rs` (`sync.rs` l.417-422) : le commentaire des modules écrits à la main est figé.**
    - Il est écrit `Hand-written: ay flat sync|check|list` quel que soit le nom du module.
    - Correction : tirer le commentaire du manifeste.

16. **Tests de `bre.rs` : `(r"k\{40000\}", "Regular expression too big")`.**
    - Ce test dépend de `MAX_REPETITIONS`, mais l'erreur `TOO_BIG` peut aussi venir de `regex::Error::CompiledTooBig` (l.600) pour d'autres motifs.
    - Aucun test ne couvre ce cas.

**Ce qui tient** : les tests SPDX couvrent les cas `OR`, `AND`, `NOASSERTION` et les expressions malformées. La forme du manifeste par fork est cohérente.
