## Alignement sur la politique

| Règle POLICY                  | État unixwin                                                                                                                                                                                             | Décision                                                                                                                                 |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Un canal par composant     | niubash : release amont (`tools.toml`, sha256 `SHA256SUMS`) pour la première installation ; fork aphrody-labs pour le binaire en service (il porte des correctifs : repli `/src`, `pwd -W`, cross-build) | Conforme à la règle 1.3 (fork épinglé par commit quand il porte un patch). Canal unique du binaire en service : [BUILD.md](BUILD.md).    |
| 2. Un lock par écosystème     | les dépôts unixwin gardent leurs propres `Cargo.lock` (unités `third_party/` construites par leur propre système, comme Chromium)                                                                        | Pas d'intégration au workspace Cargo racine : niubash et rubash se construisent dans leur dépôt (`--locked`).                            |
| 3. Une version par paquet     | doublons entre dépôts unixwin et le workspace src : windows-sys 0.59 (niubash) / 0.61.2 (rubash, src), sha2 0.10, crossterm 0.29                                                                         | Toléré : graphes séparés, rien n'est lié dans un binaire de src. À aligner dans le fork seulement si niubash passe à windows-sys 0.61.   |
| 5. Chaîne d'approvisionnement | niubash vérifie le sha256 du WinuxCmd embarqué (`winuxcmd-pin.json`) ; wpm refuse un artefact sans sha256 ; `install.ps1` du site s'exécute sans vérification (`irm \| iex`)                             | `install.ps1` est exclu de src. Le binaire installé par `just unixwin-install` est vérifié contre le `SHA256SUMS` produit par la chaîne. |
| 7. node vers bun              | unixwin.dev (npm, `node scripts/*.mjs`), wpm-gui (pnpm)                                                                                                                                                  | Non construits par src. S'ils le deviennent, ils passent d'abord à bun dans leur fork (`bun.lock`, `bun run`).                           |
| 8. third_party à la Chromium  | 14 dépôts dans `third_party/<nom>` et 2 dans `apps/unixwin/upstream/<nom>`, clones partiels, épinglés dans `src.lock.json` (chemins relatifs)                                                            | Conforme. `bun infra/unixwin/unixwin.ts lock` met à jour les pins sans réécrire le reste du lock.                                      |
| Jamais apt                    | dépôt `apt` (archive Debian/Ubuntu signée)                                                                                                                                                               | Exclu de toute chaîne ; clone partiel sans paquets.                                                                                      |
| 9. Une seule LLVM             | cross-build prd : `cargo xwin` avec clang 23.1.4, lld-link et llvm-rc de prd (pacman), CRT et SDK MSVC en cache dans `~/.cache/cargo-xwin`                                                               | Conforme (même LLVM que le reste de prd).                                                                                                |
