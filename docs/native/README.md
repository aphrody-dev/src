# Native C, Assembly, LLVM & WebAssembly Hub (`docs/native/`)

Canonical specification hub for [src](file:///C:/src/src) — the pure C (`-std=gnu11`), Assembly (`arch/x86/entry_64.S`), LLVM ThinLTO, and WebAssembly 3.0 / WASI-SDK 34 / Emscripten 7.0 core of Aphrody.

## 1. Core Goal & Generalist Scope

Aphrody is a **generalist, cross-platform native + WebAssembly engine, OS runtime, and tooling platform** built around one shared LLVM compiler pipeline (`clang`, `lld`, `wasm-ld`, `wasi-sdk`, `binaryen`, `wabt`, `emscripten`):

- **Zero language dogmatism**: performance-critical OS, ABI, wire, SIMD128, graphics, and compatibility subsystems live once in freestanding C + Assembler under [src](file:///C:/src/src) (`aysys.dll`, `aysys.wasm`, `ay-wasm-inspect.wasm`, `wayland.wasm`). Rust (`crates/*`) and TypeScript/Bun (`packages/*`) act strictly as ergonomic typed consumers over the C ABI ([sys.h](file:///C:/src/src/include/ay/sys.h)), never re-implementing kernel/protocol/SIMD state machines.
- **Compile speed & LLM context economy**:
  - Compiling [src](file:///C:/src/src) to native x86_64 PE64 (`aysys.dll`), freestanding Wasm32 SIMD128 (`aysys.wasm`), WASI Preview 1 CLI (`ay-wasm-inspect.wasm`), and browser Wayland compositor (`wayland.wasm`) takes **< 4 seconds total** with Clang + LLD + Binaryen `wasm-opt -O4`.
  - Consolidating fragmented specs into `docs/native/` and purging 25+ redundant manifesto/ledger files reduces LLM context ingestion overhead across the monorepo.
