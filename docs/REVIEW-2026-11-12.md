## Erreurs et dettes (à assumer)

1. **Affirmations non sourcées** : V8 annoncé 15.9.85 alors que c'est 16.0.25, et des docs STACK/shell rédigées de mémoire. Correctif adopté : marquer [V]/[NV]. Beaucoup de [NV] restent dans docs/shell.
2. **Trois sessions sur le même sujet** (shell : brush, niubash, brush) : travail perdu, réglages qui se marchent dessus. Partage décidé ensuite : nt-03 au bas niveau, cette session sur Chromium.
3. **WSL** : build d'une distro lancé, puis interdit. Du temps fr1 perdu ; tout est nettoyé.
4. **Forks en masse** : 210 forks vercel-labs d'un coup, 175 refusés par l'anti-abus GitHub (403). Doublons (-1/-2/-3) entre sessions. Un fork ne sert que s'il est patché ou vendorisé : la plupart ne le sont pas.
5. **Secret** : le token gh a été écrit dans un script /tmp sur fr1 (supprimé à la fin) et passé dans des URL git (visibles dans ps). À éviter : utiliser un credential helper. Le token est à faire tourner, comme les secrets déjà exposés plus tôt.
6. **NativeLink lancé en root au premier déploiement** : n'importe quel pair du mesh pouvait exécuter des commandes en root sur prd et fr2. Corrigé : DynamicUser, ProtectSystem=strict, NoNewPrivileges. Effet de bord ouvert : les actions échouent en « Permission denied » à l'exécution de clang (bit exécutable ou montage), à corriger avant le premier build distant.
7. **Test distant lancé pendant le build local** : il était en concurrence sur fr1, l'utilisateur l'a arrêté. Les tests REAPI se font quand fr1 est libre, ou depuis prd.
8. **Agent Oils** : livré. OSH 0.38.0 natif Windows (clang-cl/lld), 2,5 Mo, 36/36 smoke, boucle 5,5× plus rapide que brush ; fork() remplacé par exécution in-process + CreateProcessW. Limites : écrivain infini in-process bloque, sortie >16 Mo, pas de job control (docs/shell/oils-windows.md). Transmis à nt-03.
9. **ROADMAP.md (M0–M6 : runtime JS, bundler…)** ne correspond plus à la vision actuelle (labs = Chromium optimisé). Voir la nouvelle section Fabrique.

## Principes pour la suite

- Mesurer avant d'affirmer (temps de build, taux de cache, tailles).
- Une seule session par sujet ; ici : Chromium, ChromiumOS, NativeLink.
- Ne réécrire en Rust que ce qui gagne du temps mesurable : orchestrateur, sync, publication. gn, siso et chromite restent upstream.
